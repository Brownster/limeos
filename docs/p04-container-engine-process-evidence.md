# Authenticated Engine and running-PID evidence

RW-040 now has a GET-only executor-container library that authenticates each Unix connection, double-inspects complete selected Docker declarations and host PIDs, and freshly reacquires those facts without renewing their original lifetime. It adds no route, RPC, executor command, policy ceiling or storage effect. The current declaration endpoint keeps its existing wire format and behavior, including legacy inspection fixtures without `State.Pid`.

The trusted in-process runtime caller constructs `Docker` from a package-selected absolute socket path and supplies `EnginePeerPolicy::root()`. The policy has no public UID override or deserialization. Every stream requires kernel peer UID 0 before the HTTP handshake or any request bytes. The library retains an `O_PATH` socket descriptor and checks its device/inode, UID, mode, single link and current name around every authenticated request. Wrong initial socket type/owner/mode refuses; observed replacement invalidates existing evidence.

All socket path components must resolve without symlinks or magic links using `openat2`; unavailable kernel protection refuses. On ordinary Debian, `/var/run` is a symlink to `/run`, so the future protected runtime must select the canonical **`/run/docker.sock`**. Today's advisory runtime continues to use `/var/run/docker.sock` and is unchanged. Socket selection, protected ancestors/ACLs, host namespaces and exclusion of trusted root/same-UID writers remain runtime responsibilities. Retaining a socket descriptor and comparing its name does not freeze changes between observations.

Kernel peer UID and the retained socket authenticate a trusted endpoint. They do not distinguish Docker from another trusted root server or independently identify the daemon process: socket activation can report credentials from the listener creator. No peer PID is treated as retained daemon identity. Successful unprivileged fixture servers use an internal test-only policy; rootless production engines remain unsupported.

`Docker::inspect_storage_processes(policy)` returns an opaque `EngineStorageProcessEvidence`. Its borrowed `declarations()` contains running, stopped, unmanaged and mountless consumers. Its borrowed `running()` returns one full `ContainerSnapshot` and non-system Linux PID for every running consumer, with immutable accessors. Running PIDs must be unsigned integers from 2 through `i32::MAX`, unique across consumers. Stopped consumers require zero PID and have no running binding. Missing/negative/fractional/string/overflow PIDs, incomplete membership and unsupported declarations refuse the complete result.

Each consumer's same inspect response supplies selected snapshot, mounts and PID. The second inspection must match all those facts. Complete enumeration and Engine identity bracket both passes. `revalidate()` performs fresh authenticated complete collection, compares all selected facts and checks the original clocks before and after I/O. The outward declaration timestamp starts before socket acquisition; a new read cannot create a later issue time or extend the original five-second monotonic lifetime. Reports are Serialize-only observations; no public constructor or record import reconstructs the owner.
