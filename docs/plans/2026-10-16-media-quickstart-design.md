# Media quickstart preparation

Continue Stream B from `f4514d4` with pure preparation for the frozen eight-member
`media-server` bundle. Derive directory requirements and numeric ownership from
the existing validated storage contract. Keep the frozen order: VPN,
Transmission, SABnzbd, Prowlarr, Sonarr, Radarr, Lidarr, Jellyfin. Preserve all six
library and nine completed-download directories plus incomplete downloads.

Accept an exact stack/Engine/project target, typed VPN/timezone/numeric-identity
options and an optional complete catalog/declaration observation. No template
strings, arbitrary override dictionary, URLs, keys or VPN environment contents
enter the model. Managed UID/GID win over valid conflicting requests, with an
explicit diagnostic. Refuse VPN-off as unsupported, invalid paths, root overlap
and generated paths beyond bounds. Timezone syntax is checked, not tzdata presence.

Only fresh, complete, exact-scope observations can classify existing/new stack
intent and missing members. A failed read never means a new stack. Use explicit
`(app, stack)` mappings: matching managed canonical services are already declared,
not verified installed; duplicates, noncanonical mapping, unowned/operator
services and unregistered same-name declarations block. Do not interpret a 409
message as equivalence. Existing stacks remain existing even when VPN is present;
new-target selection belongs to the whole proposal rather than the first member.
Count unrelated declared services plus only missing bundle members against the
existing catalog service ceiling; overflow blocks install/profile candidates.

Emit an ordered workflow proposal: review complete sources/storage, prepare
directories, prepare catalog files, configure quiescent download clients, start,
independently verify startup, seed, independently verify loaded configuration,
save the profile, independently verify the profile. Missing initial client files
need a protected bootstrap/quiesce path before configuration, not fabricated empty
config. These steps are dependencies for future integration, never dispatched
commands or positive receipts. Missing terminal status, a nullable return code or
unverified seed events cannot satisfy the verification barriers. No durable
workflow state/transaction/receipt schema is invented.

A version-two portable profile draft contains only selected timezone, managed
identity, roots and fixed members; it replaces the unsafe arbitrary `values` bag
in the proposed format. It has no completion marker. Saving/migration remains
central/P06. Missing or blocked catalog observations return no install or profile
candidates. Keep six protected-source/target, physical-storage/ownership,
complete-template/VPN, authority/locks, before-image/quiescence/recovery and
independently verified-result gates unresolved for every outcome.

Prefer this bounded preparation boundary over simulating unregistered effects or
copying legacy executable payloads. Full VPN templates remain unsupported by the
current catalog projection (including its eight-port ceiling); planning this
workflow does not accept or bypass those limits.

Bound declarations/mappings to 16, selected names to 64 bytes, roots/generated
paths to 512 bytes, selected text to 32 KiB and streaming report to 64 KiB. Retain
the inclusive 90-second original sample bound. Test frozen bundle/layout fixtures,
all three storage profiles, managed identity, scope/age/unknown failures, mapping
conflicts, existing/new selection, ordering, path bounds and profile privacy.
Use local unfiltered leaf tests, Clippy, Rustfmt and helper checks; shared roots,
Store/schema/protocol, API/UI mounting, publication and hosts remain unchanged.
