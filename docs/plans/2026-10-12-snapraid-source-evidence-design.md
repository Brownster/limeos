## Boundary

Add only `executor_storage::protection_sources`, its private tests and dedicated
documentation/evidence, plus one additive public module export. No dependency,
domain/generated contract, existing inventory/collector, executor protocol,
Store/schema, worker, capability, service, packaging or UI change belongs here.
No SnapRAID process, sync, configuration write, mount/unmount or host effect runs.

The public asynchronous collection operation borrows a genuine
`StorageInventoryEvidence`, generated by the existing protected raw collector.
It accepts trusted typed storage, pool and SnapRAID configuration, explicit
path/descriptor/report limits and cooperative cancellation. Bounded counting
serialization precedes planning/cloning; generate all requirements using the
existing planner rather than accepting caller-supplied path observations.

Return an opaque `ProtectionSources` owner borrowing the original inventory and
retaining no-symlink object/parent descriptors. Reports expose the existing
`ProtectionSourceEvidence` projection plus a configuration identity. They cannot
reconstruct the owner or authorize an effect. Revalidation brackets whole-path
checks with the original inventory's UUID/signature/topology/swap/fstab/mount
checks. Neither wall observation time nor the original monotonic lifetime is
renewed. A four-second local lifetime further bounds this owner; synchronous
filesystem calls still need independent worker supervision at integration.

Every ordered source/data/content/parity requirement must bind a unique expected
filesystem UUID, supported ext2/ext3/ext4/xfs type, configured serial, full-root
writable data mount, non-boot/non-swap backing and exact statx device/mount IDs.
Reject raw nested mounts, binds/foreign roots, duplicate identities, malformed
or incomplete facts, unsafe types and missing directories. Content/parity may
be regular single-link files or absent leaves with a retained existing parent
on the verified selected filesystem. Bare directory existence is insufficient.

Use a retained host-root descriptor and openat2 IN_ROOT/NO_SYMLINKS/
NO_MAGICLINKS with O_PATH to avoid blocking on FIFO/device candidates. Reopen
names through the same retained root and compare object/parent inode, mount,
device, ownership/mode, link count and metadata timestamps. Recheck absent
names; appearance, replacement, unlink, changed mount or stale facts refuse the
whole collection. Ordered duplicate Source/Data requirements share one pinned
path while preserving every report row. Configuration remains a trusted caller
input; source directory ownership alone is not a configuration or writer lock.

Admission is conservative before opening: at most 128 report paths and 128
additional retained descriptors, with one root and two per distinct path.
Parent handles for absent leaves count too. Report limits are explicit up to
64 KiB; no production defaults, cap increases, partial results or fixture
fallback exist. The borrowed raw inventory and transient traversal handles add
separate costs. Later whole-worker admission remains required.
