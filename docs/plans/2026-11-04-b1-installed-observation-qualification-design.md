# B1 installed container observation qualification

The current source has a registered fair observation timer, authenticated
schedule/history APIs and in-app publication. Native fixtures establish the
protocol and Store rules; the actual Core binary has only demonstrated refusal
of an unprivileged reader. B1 still needs a successful installed root-reader
journey before its first milestone can be accepted. A1's mount-census churn
barrier is independent and remains open.

Use one standalone disposable Debian guest with the existing signed AMD64
packages, exact canonical non-build runner and unchanged 1,024-MiB allocation.
Reusing the full A1 scenario would stop at its unrelated mount gate and mix
acceptance scopes. A synthetic RPC server would leave genuine installed root
trust and the sealed worker untested. The standalone scenario therefore runs
the real package units, protected reader and real packaged Docker daemon.

The fixture refuses before effects unless it is root in the runner's disposable
hostname. It installs only the exact supplied signed package version and fixed
Debian fixture dependencies. Docker uses a real daemon-owned socket, rather
than a proxy or systemd-owned socket. A local BusyBox rootfs supplies one exact
full-ID container with `unless-stopped` restart policy. Only the fixture changes
that container's state. LimeOS itself performs observation and in-app delivery;
no external send, mount, stack deployment or recurring effect is authorized.

Bootstrap/enrollment and observation self-enablement use the actual control/API
paths. Current administrator grants, session/CSRF and password verification stay
in force. No test credential, clock, policy predicate, resource limit or trusted
image override enters a production binary. Keep the installed reader ceiling
and ordinary collectors unchanged. The operator explicitly starts the dormant
reader only inside the disposable guest.

Exercise the public fixed observation schedule API and policy API. Use a real
30-second interval and ordinary wall/monotonic clocks; set the supported policy
failure threshold to one through its authenticated POST. Record all changes.
Mutation requests are sent once, never automatically retried after a lost reply.
Bounded GET/SQLite observation may wait for asynchronous state, but may not
repair jobs, clear claims or manufacture receipts.

Acceptance requires these joined facts:

1. Signed package installation, exact executable/UI/package hashes and actual
   schema version derived independently from delivered committed Rust source.
2. The real root reader, original service ceilings, kernel Core peer identity,
   authenticated Engine identity and actual full-ID stopped container.
3. Creation/permission/CSRF/Origin failures leave schedule history unchanged.
   Valid creation yields a registered scheduled/partial view. Collection creates
   the exact container incident and delivered in-app notification through Core's
   ordinary timer, without direct fixture settlement.
4. A real Core SIGKILL and automatic restart preserve the original incident,
   occurrence/job/notification identities. A bounded stable observation period
   introduces no duplicate incident, occurrence tuple or job. The same human
   session remains usable after restart.
5. Starting the same fixture container produces independent Engine running
   evidence, a clear alert and exactly one delivered recovery linked to the
   original incident generation. Read-only pages remain partial. Acknowledgment
   and schedule pause use current revisions; stale changes refuse.
6. Paused state and acknowledged notification survive another actual Core
   restart. The fixture never deletes observation history or bypasses its
   immutable triggers. Final source-bound output distinguishes each completed
   checkpoint from any unexercised scope.

The fixture keeps bounded structured failure evidence before stopping its own
units and whole-VM disposal. Read-only snapshots include current schedule,
occurrence/result/alert/outbox rows and selected unit/resource facts, excluding
passwords, session tokens and private keys. Preserve failed attempts and original
process identities; verify owned QEMU/runner/container cleanup afterward.

Meaningful local reference cases cover the root/hostname pre-effect guard,
SQLite handle closure, exact occurrence/notification identity checks and negative
assertions. Scoped lint/format and repository checks precede the VM run. Freeze
fixture/product maps separately when reusing packages: new test files do not
inherit package provenance merely from the same branch name. Build/UI/package
evidence remains bound to its original source. No product change is assumed.

This scenario is installed AMD64 API/runtime qualification. It does not establish
installed browser interaction, current ARM64/Pi, upgrade/return, 24-hour soak,
remaining health sources, external channels, reviewed retirement/compaction,
full RW-042/044/045, A1/P04 or P05/P06 completion. Those gates remain required for
replacing Holly's frozen application. No production host is accessed.

## Read-only failure boundary observations

The [first installed attempt](../rewrite-evidence/p04/2026-11-04-b1-installed-observation/README.md)
creates the schedule but reaches no first settlement. Its storage inventory
probe cannot identify the container-health boundary. Keep the original timer,
75-second incident wait, setup, policy and every acceptance assertion unchanged.
Add observations only after the original failure and before whole-VM disposal.

Capture one authenticated schedule GET, preserving final runtime phase/attempt
time, followed by one independent `ContainerHealth` RPC under the actual kernel
Core UID and host-access group. The latter uses a fresh random nonce, the fixed
installed reader socket, an authenticated root peer, at most one 64-KiB frame
and an original four-second absolute deadline, with a five-second subprocess
ceiling. Frame fragmentation, early EOF, oversized lengths and late reads must
refuse. It is a later observation; it cannot establish the timer's historical
reply, freshness, admission or settlement. Never copy its cohort into Core or
retry a mutation. No root/clock/image override is added to a product binary.

Independently capture selected Core/reader unit properties, process identity,
status and FD counts plus bounded cgroup memory/task counters. Missing,
over-budget or refused sections explicitly report unavailable and preserve
the other sections and original exception. Do not stop collectors to obtain a
reply. Credentials and passwords are excluded. Limit the whole new observation
to 96 KiB and print it separately from the main failure packet so aggregate
failure-output fallback cannot silently discard the boundary evidence.

Native cases exercise fixed framing/deadline/peer checks with private mocked
I/O, per-section isolation, output bounds and unchanged original error behavior.
They establish no installed root trust. Freeze the changed fixture separately
from the unchanged package build, retain the first failed attempt and run one
distinct source-bound disposable guest before deciding on a product correction.
