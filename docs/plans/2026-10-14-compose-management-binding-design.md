# Retained declared Compose management binding

Base: local main `cbae3a8`. Retained Engine membership and protected Compose file
owners remain separate. Bind one explicitly selected stack through a protected
management catalog without treating P03 preview approval as effect authority.

## Management configuration and selection

The existing P03 catalog has no root/Engine mapping. Add a separate unregistered,
version-one management catalog: expected Engine ID and at most eight registrations.
Each registration declares a P03-compatible stack ID, Engine project name,
canonical working directory, one recognized operator filename/raw SHA256,
explicit absent/present managed-file expectation/raw SHA256, and up to sixteen
distinct supported service names. This is root-controlled configuration, not a
principal permission, human approval or executable plan. No catalog is installed.

Read one explicitly selected catalog path through the existing protected
root/namespace/traversal/hash primitives. Require effective UID 0 before access.
Keep closed fields and duplicate-field refusal, bounded strings and vectors before
growth, 16 KiB raw catalog bytes, 4 KiB metadata report, four-second original
lifetime, two-second cooperative work passes and 1 MiB lifetime requested reads.
Retain root/namespace/ancestors/file, compare fresh and held identities/content,
and rewalk names afterwards. A missing/invalid catalog never becomes an empty map.
Reports contain identities/raw hash, never catalog body bytes.

Validate every registration, including unselected ones. Stack/project names,
working directories and selected files must be unambiguous. Supported roots are
component-disjoint; duplicate or nested roots refuse. Preserve literal directory
case and meaningful operator/managed file order. The caller selects only a stack
ID from the retained catalog. It cannot override Engine, directory, file, digest,
service set, UID, clock, root or numeric limits.

## Genuine owner composition

The public async factory acquires the protected catalog, fixed-endpoint genuine
Engine Compose owner and catalog-selected genuine file owner. Require the expected
Engine ID, same retained root/mount view, exact directory and ordered file names,
and raw file digests to match. Join complete Engine membership to the selected
project and allowed service set. Keep original full container identity, replicas,
one-offs, stopped and mountless members. Unrelated and non-Compose members remain
in the complete Engine report; their stack files are not bound. A differently named
project overlapping the selected root/files refuses. Explicit registered stacks
may have zero observed members; this grants no safe absence or deletion authority.

Retain the actual three child owners, selected resource `stack:<id>` and bounded
member indices. Serialize one borrowed report without cloning owner snapshots or
building a report buffer. Bound it to 80 KiB and preflight at most 38 retained FDs:
18 for the catalog, 19 for selected stack files and one authenticated Engine socket.
Additional root/file validation descriptors remain bounded by existing primitives;
this is not combined-worker resource/RSS qualification.

Start an original four-second composition window before collection. Preserve all
child issue times, expiries and spent ledgers. Bracket genuine Engine revalidation
with catalog/file revalidation and check names/hashes/mapping again. Async timeout,
failure, cancellation/drop, reentrancy, concurrency or unwind permanently poison
the binding owner. Expose reports rather than child-owner accessors, so child
validation cannot restore a failed binding. Synchronous kernel work still needs
independent supervision. Multiple files/Engine checks are observations, not a
writer transaction; later locks and effect-time checks remain mandatory.

## Local proof and boundaries

Use production protected file code with private scratch-root/UID/clock fixtures
and the existing owned authenticated Unix-listener Engine fixtures. Test closed
catalog shape/count/string/path/digest limits, invalid unselected registrations,
duplicates/nested roots, raw changes and protected path/file refusal, original
age/read budget and poisoning. Test actual catalog-selected file/hash/Engine/
service/order/root matching, complete membership and unrelated rows, overlapping
project refusal, zero observed members, bound reports/descriptors, fresh child
changes, late cancellation, dropped async validation, reentrancy and original
expiry. Compile-fail tests prevent importing reports/owners. Public nonroot refusal
must precede callback, target and canonical Engine access.

Record lossless diagnostics and exact-source accepted logs with source/artifact
hashes, full Rust/strict Clippy/fmt/contracts/repository and local ARM64 harness
checks. Build/cache/new file scratch stays on disk; only precompiled existing
storage fixtures use small owned cleaned tmpfs runtime. No Pi, SSH, real Docker,
block probe, guest, reserved backup or external qualification path.

P03 catalog/approval, generated/wire schemas, Core/Store, claims/locks/recovery,
worker/probe resource model, service guards and package activation stay unchanged.
Protected management declarations do not validate YAML, `.env`, includes,
interpolation or combined Compose semantics; these need a later approved typed
adapter. Principal permissions, fresh executable approval, complete physical
consumers, independent review, public root/namespace/installed/resource/performance
qualification, P04/defect gates and cutover remain open.
