## Operation and current inputs

Add `limeos_backup_archive::recovery::reconstruct(expected: &BackupPreparationBinding, current: CurrentInputs<'_>, cancelled: &dyn Fn() -> bool) -> Result<PreparedRestore, RecoveryError>`. `CurrentInputs` contains borrowed opened `CustodyRoot`, `StagingRoot` and `PreparationRoot`, the full current `AdmissionPolicy`, current `CustodyLimits`, an owned current `Selection`, copied `PreparationLimits`, and a borrowed `workspace_policy_identity: &str`. Selection moves into the genuine plan rather than being cloned before validation. Roots remain caller-owned descriptors; no destination is opened by this operation.

Expected and current inputs are distinct. The current workspace identity must be independently supplied from trusted current configuration; the library never copies it from expected metadata, derives it from the expected digest or supplies defaults. Production derivation and filesystem trust protection remain unavailable. Test identities are explicit synthetic attestations. Validate the closed expected binding and current 64-character lowercase hex identity before archive I/O, then poll cancellation.

Recover only the exact named custody record through `custody::recover`, re-admitting actual stored bytes with the full current policy and finite limits. Stage a fresh catalog through `RetainedArchive::stage`. Poll before and after the bounded, existing `preparation::plan` call. Compare the recovered custody binding, genuine plan identity, ordered selected resource IDs and independently supplied current workspace identity against every expected binding field. Refuse a mismatch before calling `preparation::prepare`, so no private replacement is created from a mismatched proposal. The archive's verified manifest bounds the clone supplied to the existing plan API.

Admission policy limits and preparation limits are identity-bound. Custody limits are operational read/encoding ceilings; invalid or insufficient values refuse reconstruction, while a sufficient increase need not change the binding. No extra custody-limit field or production default is added.

On a match, call genuine `preparation::prepare` with the plan's current selection and limits, then consume the genuine prepared owner and catalog in a private production finalization helper. Return only the ephemeral `PreparedRestore` after explicit catalog discard and a final cancellation check. The caller uses its existing checked readers and explicit `discard`. No retained custody is discarded, no directory is scanned, and no stale staging/preparation attempt is adopted.

## Primary refusal and cleanup ownership

Expose a closed `Failure` enum: `InvalidExpectedBinding`, `InvalidCurrentWorkspaceIdentity`, `BindingMismatch`, `Cancelled`, `Custody(CustodyError)`, `Plan(PreparationError)`, `Preparation(PreparationError)` and `CatalogDiscard(StagingError)`. `RecoveryError` owns `failure: Failure`, `catalog_cleanup: Option<StagingError>` and `prepared_cleanup: Option<PreparationError>`. Existing nested custody/preparation errors retain their own primary and cleanup reports unchanged. These fixed slots preserve at most two independently owned cleanup failures without a provider hook or unbounded failure list.

Before a prepared owner exists, plan/cancellation/mismatch/preparation refusal remains primary; explicitly discard the fresh catalog and retain its cleanup error separately. After a prepared owner exists, cancellation consumes and explicitly discards both owners, retaining both cleanup errors if necessary. A successful preparation followed by catalog-discard refusal returns that catalog error as primary and consumes/discards the prepared owner, retaining any prepared cleanup report. It returns no successful owner. After catalog discard succeeds, cancellation before return still consumes/discards the prepared owner. Cleanup failure never promotes saved metadata, erases the primary refusal or publishes a success marker.

The existing staging quarantine retries failed explicit cleanup from Drop. Narrowly disarm its cleanup before the first attempt, so partial failure/ambiguity is not silently retried or transformed by Drop. This private change applies to explicit discard and staging failure cleanup; implicit Drop remains a best-effort single attempt when no explicit attempt occurred. Existing preparation cleanup already disarms before attempting. No public fault/provider seam is introduced.
