# ADR 0001: P01 foundation boundaries

Accepted 2026-10-04 under the operator's permission to proceed from P00. Remaining P00 experiments stay open; P01 does not add host mutation before those assumptions are verified.

Use Rust 1.88.0 with exact workspace dependencies and a locked graph. Use rusqlite 0.40.2 and bundled SQLite 3.53.2. The initial 0.40.0 pin failed on Rust 1.88 because it used the newer cfg_select macro; upstream 0.40.2 restores compatibility. Refuse SQLite older than 3.51.3 at startup. No extension loading or custom unsafe Rust is enabled.

One bounded SQLite worker owns the connection and single-instance file lock. WAL and FULL synchronization protect authority; job intent and its audit transition commit together. An audit cap and an 8 MiB free-space reserve fail closed. Reads never update a last-seen timestamp or extend a session. Startup increments a durable generation. Unverified running/verifying jobs become needs_intervention and keep their resource locks. Executor receipt reconciliation begins with actual effects in P03, so P01 cannot automatically retry an effect.

The API depends on a backend trait; only the core composition root selects SQLite and identity implementations. Domain and policy do not import transports or databases. An additive Rust schema generator emits JSON Schema, OpenAPI 3.1, TypeScript and the SQL schema. Generated contracts are checked in deliberately; build outputs are ignored.

Serve HTTP only on loopback, behind an explicitly configured local HTTPS proxy. Accept an exact HTTPS Origin for browser mutations; never trust forwarded identity or actor names. Sessions use Secure, HttpOnly, SameSite=Strict host cookies. Password work runs in at most two short-lived Rust child processes, with fixed root-owned executable paths and bounded pipe input/output. Processes are killed on cancellation and exit after one request so KDF allocations do not remain resident. The first VM measurement retained 42 MiB in core after in-process password work; this change addresses that measured failure. Login admission, database work, connections, headers, bodies, RPC frames and deadlines are bounded. Argon2id uses 19 MiB, two passes and one lane. Pi timing qualification remains necessary before cutover.

Enrollment is a root-only local RPC with a 15-minute, replaceable, one-use token. There is no network enrollment endpoint and no default identity. Tokens and session secrets are stored as digests. Sessions bind to current grant revision; task authority additionally binds service UID, task, exact scopes, expiry and core generation. Import primitives accept supported Werkzeug hashes only and preserve administrator access; the full source inventory/import workflow belongs to P06.

Ship one Debian package with distinct core, container and host services. Only the host executor runs as root. Only the container service receives Docker's group. Independent root-owned executor ceilings currently permit only health; their protocol has no effectful operation. Existing ceilings survive reinstall. Root binaries, UI and schema payload live under /usr/lib/limeos. systemd sandboxes deny writes to package paths, swaps and core dumps. The root executor currently has no capabilities; mount namespace/capability policy must be reviewed and tested when P04 introduces mounts.

The apt repository requires an operator-managed signing key and fresh signed metadata. Tests generate a disposable signing key only. No signing key is created for production, uploaded or published automatically. Package removal keeps authority, accounts and operator state; recovery starts by reinstalling the compatible package. Automatic schema rollback and the production release updater belong to P04.
