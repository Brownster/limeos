# ADR 0005: approved Compose planning foundation

Status: accepted for the authorized P03 continuation, 2026-10-05. Covers the remaining RW-032 foundation; deployment execution belongs to RW-042.

Core selects a stack and template from an optional root-owned `compose-catalog.json` beside `core.json`. HTTP and task callers supply only those two identifiers. The catalog contains a bounded, normalized snapshot of the stack, operator Compose file fingerprints and typed templates. The initial schema covers pinned images, numeric users, ports, named volumes, bind mounts, devices, privileged mode and host networking. Unknown fields, interpolation, relative paths, ambiguous operator filenames and duplicate service names fail validation. Unsupported Compose features require a later typed adapter; arbitrary YAML or shell commands cannot enter a preview.

The catalog is a planning snapshot, not a fresh observation of the host. Plans show additions, removals and changes, preserve source fingerprints and name a separate managed override file. This phase never reads, rewrites, applies or deletes operator Compose files. P04 must resolve live paths without symlink escapes, compare fresh file/mount identities, validate the combined Compose project and acquire the stack lock before any effect. A preview approval cannot be submitted to the container job system. Deployment requires a new executable plan and fresh approval in P04.

Normal previews require an explicit deployment grant for the stack. Privileged mode, host mounts, devices, Docker sockets and host networking additionally require an exact elevated deployment grant bound to the stack, template identifier and canonical template digest. A wildcard does not satisfy that elevated grant, even for an administrator. Media and container grants do not grant deployment. Task tokens must include every required scope and may propose but never approve. All transports use the same policy and persistence path.

Authority schema v5 adds a separate Compose plan table. Plans and approvals are durable, principal-scoped, revision-bound and expire after five minutes. Approval accepts only the stored digest, checks the current catalog snapshot and rechecks grants; cancellation revokes the preview. Reads do not write or refresh expiry. No default elevated grant or catalog is installed. A missing catalog disables this optional feature; an invalid catalog is preserved and rejected.
