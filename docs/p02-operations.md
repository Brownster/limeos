# Read-only P02 and shadow operation

All application services and collectors are Rust. Debian 12 (glibc 2.36), util-linux `lsblk`, systemd, and a separately configured HTTPS proxy are required. Docker is optional; an absent socket reports unavailable container observations without failing host reads.

Build with the pinned Rust toolchain and committed lockfile, build the frontend, then run `uv run packaging/build.py --arch amd64 --binaries target/release --version 0.2.0 --profile shadow` (use arm64 and the ARM64 binary directory for Pi). The `limeos-shadow` package coexists with `limeos` and the frozen Python service. It uses `/usr/lib/limeos-shadow`, `/etc/limeos-shadow`, `/var/lib/limeos-shadow`, `limeos-shadow-*` service accounts/groups/units, and separate runtime sockets. It defaults to `127.0.0.1:8004` behind `https://limeos-shadow.localhost:8444`; use a distinct hostname as well as a port because cookies are shared between ports on the same hostname. The shipped Caddy example is documentation, never installed into a running proxy automatically.

During an agreed quiet window, record current service states, container identities/statuses, mounts, existing package list and current-build state hashes before installing. Install the shadow Debian package from a signed apt repository. Set the exact shadow HTTPS origin in `/etc/limeos-shadow/core.json`, configure an independent proxy listener, and restart only the shadow services. Do not reuse the current build's login, files, database, port, or cookie origin. Core/assistant accounts must not join `docker`; only the shadow container executor may access that socket.

Enroll using `/usr/lib/limeos-shadow/limeosctl --socket /run/limeos-shadow-core/core.sock bootstrap` and the same command ending in `enroll`, passing the enrollment JSON on stdin. See the P01 guide for the secure local enrollment procedure. Never place passwords in argv or shell history.

Fresh installs enable only the appropriate host or container read ceiling. Upgrades preserve existing ceilings exactly: old P01 health-only policies deny observation reads by default. An operator enabling reads must explicitly add `allow_host_read: true` to the host policy and `allow_container_read: true` to the container policy, leaving the opposite field false, then restart the relevant executor. Both policies remain root-owned and non-writable by service accounts. There is no mutation request in this build.

The overview and resource endpoints serve cached evidence. Failed sources retain old records with an unavailable state; expired successful samples become stale. Resources absent from a successful later inventory are marked missing. UUID-less disks use serial or device-path identities; these fallbacks are observational and cannot support destructive-operation approval. Mount pools are observed kernel mounts, not imported legacy storage configuration. Offline configured disks/stacks not discovered by this instance are not claimed as inventoried; importing their configuration is a later migration step.

System history records independent minute readings with five-minute transactions, fixed 24h/7d/30d reporting ranges, 31-day retention and an 8 MiB SQLite ceiling. The last unflushed readings may be lost on abrupt shutdown because telemetry is disposable. History failure does not affect authentication or authority state. **Earlier 31-day history stays in the existing build's System history view.** Keep that view available throughout shadow comparison; no legacy history database is opened or deleted. The dashboard states this separation.

SSE connections deliver full snapshots on every reconnect, rechecking current grants at least every five seconds. Limits are eight readers, 25 seconds, and 128 KiB per stream. Normal reconnection is expected. The UI also refreshes while visible if a proxy interrupts streaming. No event history or mutation receipt replay is implied.

To finish comparison, verify the measured workload (20 containers, eight disks, three dashboards), CPU/PSS, authenticated HTTP p95, readiness and storage-write budgets on the reference Pi. Record actual results; fixture/VM numbers do not substitute for hardware qualification. Remove with `apt remove limeos-shadow` and remove only the explicitly configured shadow proxy listener. State/accounts/ceilings remain for safe reinstall, as in P01; compare reference mounts, containers and current-build hashes with the baseline. Installation necessarily creates shadow package/service/account state, but must not alter existing application, storage or container state.
