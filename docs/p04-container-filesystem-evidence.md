# Container filesystem dependency evidence

RW-040's `inspect_container_dependencies(contract, containers)` library function binds fresh protected storage probes to the [retained container source descriptors](p04-container-source-evidence.md). It requires UID 0 in the host mount namespace. It takes a validated storage contract and the existing five-second Docker inventory, collects both evidence sets itself, and retains their handles until its result is dropped. No serialized snapshot can reconstruct those handles.

`ContainerDependencyEvidence::snapshot()` returns a version 1 read-only report. The report binds the full contract, Docker inventory, storage inventory and source snapshot digests, the host root mount ID and the complete raw mount-table digest. The existing wire storage inventory's selected-row digest remains unchanged; the collector checks both formats explicitly rather than comparing unlike digests.

Each configured assignment includes consumers identified by full container resource ID and container destination. Each match names the source's actual mount ID and freshly probed filesystem UUID. `same_filesystem` means the source and assignment use the same block filesystem, including a bind alias whose visible path has no lexical overlap. `shared_backing` means the source's filesystem belongs to the same conservative connected block graph. Sibling partitions therefore count conservatively; the report does not imply that unmounting one partition necessarily affects its sibling.

Ordinary symlinks, named-volume paths, regular-file sources, stopped consumers and nested directory mounts use the existing source collector. Their declarations are bound in full, including volume driver/name and container image/running/start facts; the binder does not filter stopped containers. Every source candidate must match the retained full mount table and a direct block signature. A successful explicit tmpfs candidate with device major zero has no block backing, but nested candidates are still checked. Missing UUIDs, duplicates anywhere in the probe inventory, missing topology nodes, unsupported/unknown source filesystems, unprobed loop devices and btrfs backing are refused. Configured boot/swap backing and filesystem/serial mismatches are refused too.

`StorageInventoryEvidence` now retains every raw block descriptor and its signature, including devices without a filesystem, the sysfs graph, swap snapshot, complete mount digest and protected fstab descriptor. Its revalidation re-probes every descriptor and checks the surrounding context before and after probing. It also compares retained and freshly opened fstab inode/device/mount identity, so replacing fstab with identical bytes cannot preserve the evidence. The existing `inventory()` function uses this collector and returns the same wire shape.

Combined revalidation checks source descriptors before and after re-probing storage. Observed replacement, deletion, retargeting, namespace/mount/topology/swap changes or signature changes invalidate the result. Source content changes do not change its filesystem dependency identity. Revalidation does not reacquire Docker or inspect a running container's mount namespace, and external clients can still change state between observations.

The report admits at most 512 matches across all assignments and 48 KiB of serialized output. Amplification through shared backing is bounded; output is never clipped. The combined collector has a four-second cooperative work budget with timeout-bounded async probes, and storage evidence expires five seconds after collection starts. The Docker collection-start age and remaining monotonic source lifetime still apply. Synchronous filesystem calls require a later process deadline and single-flight service admission; this library cannot independently interrupt them.

[Local source-bound proof](rewrite-evidence/p04/rw040-filesystem-binding/README.md) records 271 Rust workspace tests, including 18 new binder tests and three retained-storage tests. Most binder cases use synthetic kernel/probe facts, while fstab replacement/link cases and the existing 19 source regressions use real private unprivileged files. This proves the mapping and refusal rules, not successful end-to-end combined collection in an installed root service.

The combined function adds no command, route, executor request, policy ceiling or storage effect. Running-container namespace inspection, Engine reacquisition, pool/protection/share propagation, shared claims, root ceilings, process admission, installed collection and effect-time checks remain pending before mount/unmount operations. Mount readiness is a separate check. DSK-001, MNT-001, MNT-002 and RT-001 remain open. [ADR 0012](adr/0012-p04-container-filesystem-binding.md) records the design and eight-hour slice estimate within P04's existing 320-hour estimate.
