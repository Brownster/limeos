# Storage verifier boundary review

The read-only RW-040 adapter is a precursor to registered storage effects. It verifies a bounded typed plan and never edits fstab, starts a stack, mounts, unmounts, formats or changes ownership. A successful snapshot contains observations and is not an execution capability. Future effects must perform these checks again within their protected resource lock and durable approval/receipt path.

The privileged boundary consists of the package-owned executor, the distro-owned fixed `/usr/sbin/blkid` probe and rustix 1.1.5's safe descriptor/statx wrappers. Rustix already existed in the lockfile through tempfile and now enters the production adapter directly. Its internal unsafe Linux ABI implementation is trusted and reviewed as a native boundary; workspace first-party unsafe remains forbidden. No third-party package was added. The lockfile now has 215 audited packages because the new first-party adapter crate is included.

Read-only probes have cleared environments, null input/error streams, bounded output, three-second child deadlines and kill-on-drop. Plan files are regular files capped at 64 KiB. Sysfs topology is capped at 128 nodes and sixteen backing levels; mount tables are capped at 1 MiB and 4,096 entries. Descriptor traversal rejects symlinks and writable/non-root directory components. Block descriptors must match the kernel device number before probing, and the candidate UUID is probed twice. Topology, mount table and namespace are compared again at completion. These checks reduce replacement races; subsequent effects must retain/revalidate their descriptors and account for concurrent operations rather than reuse a readiness result.

The verifier intentionally fails closed for unknown boot topology, duplicate UUIDs, unsupported filesystem mappings, absent raw-device permissions and missing serial proof. Serial proof currently uses kernel-exposed serial attributes on the ancestry; drives exposing only udev/vendor serial data need an additional fresh adapter. Btrfs multi-device and FUSE-backed NTFS mappings are still pending. Active swap-device exclusion, dependency shutdown and device formatting safety must be established before those effects are registered.

The short-lived readiness unit uses PID 1's mount namespace. Mount namespace sandbox directives would invalidate host evidence, so they are omitted explicitly. The unit keeps an empty capability set, no privilege escalation, syscall/address-family restrictions, bounded descriptors/tasks/memory and a 125-second watchdog. It has no install target or restart loop. The existing observer's sandbox is unchanged. Installed readiness qualifies this mechanism; the complete profile startup, API/UI, unmount and runtime-loss paths remain separate work, and MNT-001 stays open.

All mutation and failure setup in the qualification harness is confined to four empty serial-guarded virtual disks in a disposable Debian guest. Wybie, its active Python services, media data and the frozen Python checkout remain unchanged.

## Guided preview boundary

Source `dff3b30` adds a dormant root reader with an independent `allow_storage_read` ceiling and no writable request. Both RPC peers are checked by kernel UID; the core checks the current administrator storage grant before collection and after it. Reader/core admission is single-flight, evidence is capped at 48 KiB, raw probes are repeated on retained descriptors, and the core's five-second RPC deadline surrounds the reader's four-second collection deadline. Synchronous kernel I/O may stall the reader; the core still bounds its wait and returns unavailable. No partial evidence authorizes a plan.

Fstab inspection protects every path component, refuses symlinks/non-regular files/hard links, and caps the source at 64 KiB. Every byte contributes to its digest, but options and remote source strings stay inside the reader. Only UUID/raw-device/target references leave it. Invalid ownership markers or unresolved non-boot local aliases are preserved and refused. Generated UUID entries escape spaces/backslashes and use fixed filesystem options and device/mount deadlines. Pure replacement changes only the owned section and checks the exact source digest; it performs no write.

Schema 6 persists bounded owner-scoped guided previews and hashed human review tokens under the established sole durable writer. Current grants, revision, expiry, canonical digest and complete fresh inventory must agree at approval. GET review and cancellation need no live reader. There is no storage intent, queue, resource claim or receipt execution in this version; future effects require a new operation version and new human approval. Planner acceptance does not prove target preparation, media ownership, active swap exclusion or dependency safety. Ext2/3/4 and XFS rendering is the current subset; Btrfs and removable/FUSE ownership remain open.

The reader intentionally sees PID 1's mount namespace and root devices, with an empty capability set and no mount namespace sandbox. It remains dormant after installation. Package pre-removal stops optional reader/readiness units if loaded, including a manually started reader, before replacing binaries. Existing host/container service sandboxes and grants retain their established behavior. Installed qualification is recorded separately from source checks; no P04 defect row closes on this preview mechanism alone.
