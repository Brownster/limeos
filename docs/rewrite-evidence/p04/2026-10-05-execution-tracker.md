## Protected target preparation and recovery

Source `589cf9a` adds stable active-swap identity to fresh inventory and a distinct `storage.prepare_targets` root operator plan. [ADR 0008](../../adr/0008-p04-protected-storage-targets.md) and [operating instructions](../../p04-storage-targets.md) define the scope. Swap files exclude the complete connected backing graph, including sibling partitions; changing swap utilization does not invalidate identity. Guided HTTP creation/approval and readiness refuse affected assignments. Existing ordinary-device canonical JSON and schema-6 previews remain compatible and non-executable.

Preparation requires unmounted existing filesystems, protected existing parents in the host root filesystem, and absent or empty root-controlled final targets. Mounted targets hide their underlying directories and are refused. It creates final root:root 0755 directories through retained descriptors, then fsyncs and verifies them. It does not mount, format, write fstab, create media leaves or change existing data ownership. The standard installed root command is separate from the read-only RPC reader; shadow/relocated binaries refuse preparation and reconciliation. No core storage intent or HTTP write queue is registered.

A root-private bounded SQLite WAL journal commits the exact plan/digest and configuration/UUID/mountpoint claims before the first directory effect. Verified results release claims atomically. Failures or process death preserve claims, and retry returns the receipt without another mkdir. Explicit reconciliation obtains fresh complete inventory and target evidence, then records an unchanged before-state or complete verified postconditions. Partial preparation, changed evidence and unexpected data keep claims. Lookup is read-only. These private claims coordinate this preparation operation; shared core/container/share/pool dependency locking remains pending before mount/fstab execution.
