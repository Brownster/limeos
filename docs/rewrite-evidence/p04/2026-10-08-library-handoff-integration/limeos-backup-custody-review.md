## Corrections

1. **FIFO replacement can hang recovery before type validation.** `src/custody.rs:531` opens `archive` and `record.json` with `O_RDONLY | O_NOFOLLOW | O_CLOEXEC`, then validates their type with fstat. An existing FIFO waits for a writer in openat, so the subsequent regular-file refusal never occurs. Add a nonblocking object open, preserving all no-follow/type/ownership checks, and a real isolated FIFO regression that proves bounded whole-result refusal with no catalog or foreign deletion. Existing object attacks exercise directories and symlinks, but do not cover this case.

2. **JSON serialization allocates before enforcing the custody record cap.** `encode_record` at line 130 calls `serde_json::to_vec`; publication checks its length only at lines 925–927. Canonical recovery repeats that allocation at line 1163. The identity encoder already checks a streaming byte bound, but JSON field overhead and escaping can expand the temporary record beyond `max_record_bytes` before refusal. Enforce the declared cap before or while allocating the canonical JSON buffer, preserving the byte format and typed Limit/Allocation failures. Add a boundary/amplification regression that distinguishes the JSON record length from the binary identity length. The single-file RSS samples and oversized on-disk record tests do not establish this allocation guarantee.

3. **Early creation cleanup bypasses owned-inode checks, and one allocation failure has no guard.** After pending open/fchmod/fstat failure, lines 607–620 unlink its generated name without a known inode. After created-file fstat failure, lines 657–670 likewise unlink by name. These paths do not meet the assignment's conservative cleanup rule for unverifiable or replaced objects. Retain and report names whose ownership identity cannot be established rather than deleting them blindly. Also establish an armed pending guard before the fallible two-element reservation at lines 627–630; that Allocation currently leaves the created directory without the normal cleanup path. Private early-failure regressions should preserve primary and cleanup results and leave foreign replacements untouched. This does not ask the library to prevent concurrent same-UID or privileged writers, which remain outside the caller's exclusion contract.
