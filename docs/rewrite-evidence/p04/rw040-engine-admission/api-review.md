## Approved seam and behavior

- `EngineReadProfile::CombinedV1` and `Docker::inspect_storage_processes_with_profile(policy, profile)` are trusted Rust-only selection. No numeric/UID/PID/proc-root/clock limit override, importable owner, wire parameter or current runtime caller migration.
- Existing `inspect_storage_processes(policy)` keeps the standard defaults and current per-complete-pass 8-MiB body budget. Production `EnginePeerPolicy::root()` and authentication before any HTTP byte remain unchanged. No public test-authentication weakening.
- Constrained all-consumer count 16, running count 8 and selected-declaration count 32; version response 8 KiB, other responses 64 KiB, HTTP body allowance 2 MiB across initial double inspection and all revalidations. Existing 48-KiB report, original five-second owner lifetime, four-second collection/two-second request bounds and separate header/trailer limits remain. The body allowance is not a header, heap or total socket-byte claim.
- Returned constrained owners retain the profile and the same cumulative budget. Fresh collection, mismatch, cancellation or retry cannot replenish already consumed input. Live reservations may be released after temporary values/failed attempts are dropped; cumulative body/work input does not replenish. No partial snapshot or changed wire error taxonomy.
- Reuse the selected list/container semantic validators. Private optional admission hooks bound ID/resource/ContainerSnapshot/source/destination copying before it occurs. Full stopped/mountless membership counts, repeated selected declarations count separately, and the second inspection/final pass apply the same rules. Advisory missing-PID compatibility remains unchanged; protected strict running/stopped PID validation remains mandatory.

## Required implementation proofs

1. **Decoder scratch precedes the visitor.** Pinned `serde_json::SliceRead::parse_str_bytes` extends/pushes its reusable scratch Vec for escaped strings before `visit_str`; Unicode handling also reserves four bytes. `de.rs` has feature-dependent numeric and ignored-value scratch paths. The proposal correctly reserves a conservative raw-body-derived scratch allowance before decoding, separately from visitor output. Verify the actual unified feature set, capacity/reallocation overlap and active paths before asserting that twice the body cap bounds scratch. A visitor string cap alone is insufficient. If that factor cannot be supported, use a smaller supported allowance or explicit capped decoder; no speculative universal heap claim.

2. **Every owned growth is covered.** Charge node/key/string/collection growth, including unknown fields and replaced duplicate keys, before creating owned output. Decoder depth <=32, nodes <=2,048/response, collection entries <=256, decoded key/string bytes <=128 KiB and each string <=16 KiB are closed policy. The list-specific root count must stop before decoding/copying an excess member while still accepting exactly 16. Do not trust arbitrary `size_hint` for reserve or build an unrestricted Value then count it. Fixed raw-body and scratch buffers, containers, semantic clones and report comparisons need separate, explicit reservations; settle their fixed policy arithmetic in the implementation.

3. **Overlapping lifetime and concurrency remain bounded.** The retained snapshot, the second initial pass, fresh comparison Value/snapshot and decoder/raw buffers can overlap. RAII charges last until the corresponding owned allocation is dropped. Shared reservations must be atomic or otherwise safely serialized under overlapping `revalidate(&self)` calls; successful reservation must not race another call past the cap. A temporary owner cannot silently switch back to standard limits. Demonstrate that failed decode/copy/comparison/cancellation releases live reservations while preserving cumulative consumed bytes.

4. **Std allocation limits are stated honestly.** BTreeMap/serde_json::Map nodes lack a stable fallible reserve API. Bound and charge each entry before insertion; distinguish this counted node/string admission from allocator overhead and allocator-abort recovery. Vec/String owned growth is fallible and explicitly reserved. This milestone has no independent worker to turn every allocator abort into a typed result, so process containment/cgroup qualification remains later work.

## Acceptance matrix for this slice

- Isolated Engine fixtures accept the exact 16 all-consumer, eight-running and 32-selected boundaries; the next stopped/mountless/running/selected item refuses the full request before excess follow-up inspection or owned copy. Request counters/instrumentation prove the refusal location. Repeated selected sources count independently.
- Individually valid responses consume the same 2-MiB body counter across initial double inspection, subsequent owner revalidation and failed fresh attempts. A new per-collect allowance must fail the regression. No later timestamp or lifetime is minted.
- Exact/next byte, node, depth, collection, decoded-string and escaped/unknown-key boundaries cover both ordinary and comparison decode. Small raw bodies with many tiny nodes/maps cannot bypass accounted growth. Pinned scratch-capacity evidence includes escaped Unicode and the active numeric/ignored paths.
- Live-overlap and concurrent-reservation regressions prove no over-admission; failed reservation/open/decode/comparison and dropped values release live reservations exactly once. Cumulative input remains spent after failure/cancellation. Meaningful private counters prove no next growth attempt at the exhausted cap.
- Existing protected 64-consumer and advisory missing-PID cases remain valid with unchanged output/semantics. Existing real socket/root-credential refusal, socket identity, strict PID-only change, complete membership change, original issue time, wall rollback and deadline cases remain applicable. Private nonroot fixtures are accounting/transport tests, not production UID-0 authentication qualification.
- Relevant focused tests and strict workspace/repository/contracts/dependency gates bind settled source hashes and preserve failed attempts. Local owned fixtures do not use workstation Docker/storage or any engineer-owned path. Current service policies/dependencies, bin runtime/IPC/commands and frozen Python remain untouched.
