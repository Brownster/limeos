# P01 dependency, unsafe and native-code boundary audit

Reviewed 2026-10-04 against Rust 1.88.0, the supplied Cargo.lock and the P01 package fixtures. This is a boundary review and automated advisory/license check, not a manual audit of every dependency's source.

- First-party workspace crates inherit `unsafe_code = "forbid"`. Clippy compiles every target with warnings denied. A deliberate unsafe declaration is rejected by the release-gate probe.
- `cargo audit` reports zero vulnerabilities or informational warnings across 211 lockfile dependencies, including the P00 spike and build/dev dependencies. Its advisory database commit is recorded in [cargo-audit.json](cargo-audit.json). There are no advisory exclusions.
- `cargo deny` passes advisory, license, source and wildcard checks. Duplicate-version warnings remain for base64, getrandom and syn; these arise from the spike, macro/build tooling and separate RNG consumers. See [cargo-deny.txt](cargo-deny.txt). Sources are crates.io only; dependencies and the toolchain are pinned, and builds use `--locked`.
- The production core's resolved normal dependency tree is recorded in [core-dependencies.txt](core-dependencies.txt). The spike's Reqwest/Rustls client is outside the packaged services. The production HTTP boundary uses Axum/Hyper/Tokio; HTTPS terminates in an operator-configured local proxy.
- SQLite is the main bundled native component: libsqlite3-sys 0.38.2 builds SQLite 3.53.2. The worker owns one connection, uses prepared/parameterized queries, WAL/FULL synchronization, foreign keys and `trusted_schema=OFF`. The application enables no extension-loading feature or arbitrary SQL interface. Startup refuses SQLite below 3.51.3, covering the [upstream WAL reset fix](https://sqlite.org/wal.html).
- Tokio/Mio/socket2, libc, getrandom and fs2 contain platform/FFI/unsafe implementations. They supply sockets, kernel peer credentials, process control, OS randomness, file locking and free-space measurement behind safe Rust interfaces. Their crates remain part of the advisory and source gates. Resource admission and byte/time limits apply before expensive parsing or password work.
- Password algorithms use Rust Argon2id, scrypt and PBKDF2/SHA256 implementations. Stored parameters are capped before computation; comparison uses subtle's constant-time equality. A bounded, short-lived process frees KDF allocations on exit and inherits the core cgroup, UID, filesystem sandbox, no-swap setting and core-dump prohibition. No password travels in argv or the environment.
- The x86-64 executor ELF has PIE, BIND_NOW, GNU_RELRO and a non-executable GNU_STACK. Its dynamic dependencies are libgcc_s, libm, libc and the system loader. ARM64 release artifacts use the Debian 12 cross sysroot; both architectures' core and CLI use that same minimal system-library boundary. Package control requires glibc >=2.36.
- The VM walks the root executor's executable/library path components and checks root ownership and lack of group/world write access. Its actual executable resolves to `/usr/lib/limeos/limeos-executor`. Packaged payloads contain no symlinks. Core and executors cannot write package paths under the tested systemd sandboxes.
- The frontend uses pinned React and a locked Vite/TypeScript build. `npm audit` reports zero vulnerabilities. The package includes only the built static assets, not Node.js, npm or node_modules. Python, Ruff, signing tools and VM tools are development/release tooling, not production runtime dependencies.

The native ARM64 CI run, real Pi performance, proxy/browser HTTPS acceptance, future executor capabilities/mount namespaces and long-running soak qualification remain separate evidence requirements. P01 grants no effectful executor operation.
