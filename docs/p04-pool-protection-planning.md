# RW-041 pool and SnapRAID planning foundation

This slice supplies pure Rust configuration and previews, bounded read-only imports/parsers, and a port for the RW-040 reader. It registers no operation, HTTP route, process runner, migration, schedule or host effect. Preview strings are review artifacts; a future executor must validate and render again from typed protected configuration under its locks and recovery barrier.

Implementation starts from `589cf9a6de587d301ecaacff9eeb92869af40e7c` on `rw-041-pool-protection`. The frozen reference is pi-health `80593b29443ea9b81eb60ed4e5c3c3ac7a236204`. Configuration paths are canonical component paths beneath `/mnt`, retain case, and reject traversal, repeated/trailing separators, whitespace and ambiguous renderer delimiters. Such imported paths produce findings; the parser never normalizes or repairs them. This initial subset deliberately rejects paths that need fstab/config escaping. `StorageContract` retains its broader supported path format for other RW-040 work.

Golden fixtures cover the existing single-disk and separate-downloads contracts (pool/protection unconfigured), the fifteen-drive protected pool, and an ordered two-parity case with `Movies` paths and UID/GID 1100/2100. Expected text comes from isolated frozen pure renderer methods, with only the generator banner/timestamp and final newline normalized. No plugin constructor or host operation ran to build these fixtures. They are synthetic fixtures, not captured proof of installed storage behavior.

## Sync eligibility and defect regressions

`SnapraidConfig::plan` binds each configured drive root to the exact UUID, mountpoint and role in `StorageContract`. `ProtectionPathRequirement` enumerates source roots, every data path and every generated content/parity file. Pool roots apply even when disabled. Component comparisons reject pool roots, descendants and pool mounts nested inside a protection source, while accepting neighbors such as `/mnt/storage2`.

`plan_snapraid_sync` regenerates the preview rather than trusting a caller-supplied preview. It requires enabled protection, valid fresh inventory and complete ordered path observations. The selected UUID must resolve uniquely to the mounted device, with matching filesystem and configured serial, writable full-filesystem root, distinct host-root mount ID and no boot/swap backing. Missing, duplicate, nested, replaced or bind mounts and unsafe/unavailable descriptor observations fail. Source/data paths must be directories. Content/parity leaves may be regular files or absent files with an independently verified safe mounted parent; an existing bare directory never suffices.

Source and diff completion observations must be within five seconds of the supplied planning time, with no future timestamps. Diff evidence binds the exact configuration, topology digest and mount digest. Fresh sources may be collected after diff completion; changed digests fail instead of rebinding an earlier result. Missing/failed/timed-out/oversized/non-UTF-8/partial/duplicate/overflowing/unparseable diff output cannot yield sync eligibility. Delete/update counts at the configured limits pass; excess counts block. There is no force parameter. Overrides must become separate authorized, audited operations in the integrator's durable path.

`CapturedStorageRead` retains real termination and both truncation flags. Parsing checks exit status before interpreting stdout, so healthy text or a success log cannot replace failed process evidence. `StorageReadFailure` keeps optional actual termination separate from parser/source failure reason. Imported log errors have no invented process exit. Errors retain bounded sanitized stderr; terminal controls and credential-bearing lines are removed. Process reads/logs are bounded to 200,000 bytes and 4,096 bytes per line; logs also have a 1,000-event limit. Human/tagged diff parsing requires a zero process exit, matching the frozen guard; alternate exit semantics need qualified fixtures before being accepted.

SRA-001 tests cover every data/content/parity observation, bare directories, UUID ambiguity/replacement, mount identity changes, unsupported fresh filesystems, boot/swap, read-only/bind/nested mounts, stale/rebound evidence, diff failure and thresholds. SRA-002 tests cover every role, generated filenames, disabled roots and prefix neighbors. MFS-001 tests cover real non-zero/timeout/missing-binary/signal/I/O/limit results despite success-shaped stdout. These are planner/parser regressions only. The register rows remain open until installed host operations and their recovery paths are qualified.

## Interfaces needed from RW-040

The [read-only port](../crates/observations/src/pool_protection.rs) is `PoolProtectionReader`: `pool_mounts` supplies a bounded display projection, `sources` supplies `ProtectionSourceEvidence`, and `snapraid_read` accepts only the closed `Status`/`Diff` query. Import/parsing functions accept bytes and captured results, so there is no arbitrary path, plugin, executable or shell API.

The protected reader must resolve a package-owned configuration selection, retain no-symlink descriptors in PID 1's mount namespace, probe fresh UUID/serial/block identities and topology, and return complete inventory including mount dependencies. For every requested path it must attest the final device/mount ID and allowed object state; an absent file needs the retained safe parent descriptor. Display caches, path existence and by-UUID symlinks alone cannot implement this contract. Protection sync evidence currently admits ext2/ext3/ext4/xfs only; Btrfs and FUSE/multi-device identity remain closed with RW-040.

Before execution, the integrator must acquire the shared configuration/device/mount/pool/protection dependency locks, collect sources, run a fixed package-owned bounded read, refresh sources after a long diff, and reject changed digests. Bind configuration, evidence and thresholds into the versioned authorized plan. Independently revalidate under executor-held locks before each effect and reconcile unknown outcomes through the durable journal. These pure previews do not supply an approval, operation version, receipt, authoritative collector, process runner or writable root-executed file.

Remaining decisions are admission of additional legacy option/settings/cron/status/tag variants, RW-040's protected selection and evidence transport, executor resource claims, and the separate audited threshold-override operation. Unsupported imports must remain visible until those decisions have fixtures and qualification.
